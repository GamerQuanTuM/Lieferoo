## 1. 언제, 어디에 쓰나

| 항목 | 내용 |
| --- | --- |
| 누가 | PM이 팀 전체의 내용을 정리해서 써요. 마케터 내용은 M2 · M3을 보고 정리해요 |
| 언제 | 최종 결과물을 NPC 팀장에게 제출할 때 (최종 인계) |
| 어디에 | 최종 제출 화면의 **문항 칸 4개** |
| 분량 | **문항별 최대 1,500자** |
| 필수 | 4칸 중 하나라도 비어 있거나 1,500자를 넘으면 **제출되지 않아요** |

## 2. 4개 문항

| # | 문항 | 이렇게 쓰세요 |
| --- | --- | --- |
| 1 | **어떤 문제를 골랐고, 왜 그것이 문제라고 봤나요?** | 고른 문제를 한 문장으로 먼저 쓰고, 고른 이유를 자료(지표, 문의 샘플, 현재 화면)에서 찾은 근거로 설명해요. PRD의 단서 선택표를 바탕으로 써요 |
| 2 | **어떻게 풀었나요?** | 무엇을 바꿨는지, 그래서 사용자의 흐름이 어떻게 달라졌는지 써요. 동작하는 웹 링크에서 확인할 수 있는 내용을 기준으로 써요. **마케터가 있는 팀**은 만든 기능을 외국인 유저 · 라이더에게 어떻게 알리고 쓰게 할지(**출시 준비**)도 써요: 핵심 메시지, 채널과 시점, 성공 지표. GTM 플랜(M2)과 런칭 에셋(M3)을 기준으로 써요 |
| 3 | **무엇을 뺐고, 왜 뺐나요?** | 고르지 않은 단서, 줄인 범위와 그 이유를 써요. **NPC 팀장의 변경 공지를 어떻게 처리했는지**도 여기에 써요 |
| 4 | **AI를 어디에 썼나요?** | AI를 어디에 썼는지 **한 줄**로 써요 (어느 단계에서, 무엇에). 쓰지 않았다면 "사용하지 않음"이라고 써요 |

## 3. 잘 쓰는 법

- **결론부터** 써요. 첫 문장만 읽어도 무엇을 했는지 알 수 있게 해요.
- **숫자와 사실**로 써요. "많이", "크게" 대신 자료에 있는 숫자나 실제로 바꾼 것을 적어요.
- **팀이 실제로 한 것**만 써요. 하지 못한 것은 3번 문항에 이유와 함께 적어요.
- PRD · QA 리포트와 **내용이 맞아야** 해요. 다르면 PRD의 의사결정 로그에 이유가 남아 있어야 해요.
- (마케터가 있는 팀) 2번에 쓴 출시 메시지가 QA 리포트 §3-1 ‘출시 약속 대조’ 결과와 맞아야 해요. 링크에서 안 되는 것을 약속하지 않아요.
- 문항끼리 내용을 반복하지 않아요. 문제(1) → 해결(2) → 뺀 것(3) → AI(4)로 나눠 써요.

## 4. 제출 전 확인

- [ ]  4칸을 모두 채웠다
- [ ]  각 칸이 1,500자를 넘지 않는다
- [ ]  1번 문항의 첫 문장이 '우리가 풀 문제'와 같다 (PRD §1)
- [ ]  3번 문항에 변경 공지 처리 내용이 있다
- [ ]  4번 문항에 AI를 쓴 곳이 한 줄로 있다 (또는 "사용하지 않음")

# English version · One-page summary guide

> You don't submit the one-page summary as a file. You **type it directly on the final submission screen**. This guide tells you what to write.
> 

## 1. When and where you write it

| Item | Details |
| --- | --- |
| Who | The PM writes it, putting together the whole team's work. For the marketer's part, the PM uses M2 · M3 |
| When | When you submit the final work to the NPC team lead (final handoff) |
| Where | The **4 question fields** on the final submission screen |
| Length | **Up to 1,500 characters per question** |
| Required | If any of the 4 fields is empty or over 1,500 characters, **you can't submit** |

## 2. The 4 questions

| # | Question | How to write it |
| --- | --- | --- |
| 1 | **Which problem did you choose, and why did you see it as a problem?** | Start with the problem in one sentence. Then explain why you chose it, with evidence from the materials (metrics, inquiry samples, current screens). Base it on the clue selection table in your PRD |
| 2 | **How did you solve it?** | Write what you changed and how the user's flow changed as a result. Base it on what can be checked on the working web link. **Teams with a marketer** also write how they will tell foreign users and riders about the feature and get them to use it (**launch preparation**): key message, channels and timing, success metrics. Base this on the GTM plan (M2) and launch assets (M3) |
| 3 | **What did you leave out, and why?** | Write the clues you didn't choose, the scope you cut, and why. Also write **how you handled the NPC team lead's change notice** |
| 4 | **Where did you use AI?** | Write **one line** on where you used AI (at which step, for what). If you didn't use it, write "Not used" |

## 3. How to write it well

- **Start with the conclusion.** The first sentence alone should show what you did.
- Use **numbers and facts**. Instead of "a lot" or "greatly", write numbers from the materials or what you actually changed.
- Write only **what the team actually did**. Put what you couldn't do in question 3, with the reason.
- It must **match your PRD and QA report**. If something differs, the reason must be in the PRD decision log.
- (Teams with a marketer) The launch message in question 2 must match the result of QA report §3-1 "Launch promise check". Don't promise anything that doesn't work on the link.
- Don't repeat content across questions. Split it as problem (1) → solution (2) → what you left out (3) → AI (4).

## 4. Check before you submit

- [ ]  All 4 fields are filled in
- [ ]  No field is over 1,500 characters
- [ ]  The first sentence of question 1 matches "the problem we will solve" (PRD §1)
- [ ]  Question 3 says how you handled the change notice
- [ ]  Question 4 has one line on where you used AI (or "Not used")
